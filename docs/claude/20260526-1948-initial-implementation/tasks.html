The seven slices

Demoable, vertical, dependency-ordered.

Each slice cuts through every layer end-to-end and produces a verifiable behaviour change. No slice is a "build the X module" layer — every slice has a Host-app developer's hand on the demo button.

01

End-to-end Verification happy path (the tracer bullet)

AFK
Blocked by none · start immediately
Stories 01 03 08 09 14 15 17 19 21 24 25 29 30 31

The thinnest possible line that proves the architecture works end-to-end: a Host-app developer can configure the gem with a Signing key, call test_mode!, send a code to a Phone in any plausible format, verify with "000000", get back a signed Token, and decode that Token into an Identity carrying the verified Phone. Every layer of the core API is built — Phone normalisation, Token encoding/decoding, Result and Identity value types, error class hierarchy, Config holder, OTP::TestAdapter, and the top-level Bitsmithy::Auth façade composing them. The redact_phone public helper is included because exception messages already need it. The Rails-env guard from ADR-0002 is deferred to slice 05.

Acceptance criteria
  • configure yields a Config; validate! raises ConfigurationError when any required field is unset.
  • normalize_phone("(555) 555-1234", country: "US") returns "+15555551234" and equivalents work for spaces, dashes, dots, raw E.164.
  • test_mode! swaps the active OTP adapter to a TestAdapter instance.
  • send_code("+15555551234") returns a Result with success? == true.
  • verify_code("+15555551234", "000000") returns a Result with success? == true and a non-nil Token.
  • decode_token(result.token) returns an Identity carrying the Phone and expires_at == issued_at + session_duration (default 86400).
  • redact_phone("+15555551234") returns "+1******1234".
  • Token carries documented claims (sub, iat, exp, iss: "bitsmithy-auth"), HS256, verifies iss on decode.
  • Each module built has at least one happy-path test.
  • bundle exec rake green; Rubocop clean.
  • bin/console smoke demo: four-line sequence walks the Verification dance.
02

Failure-path coverage for the core pipeline

AFK
Blocked by slice 01
Stories 02 04 05 11 12 18 20

Extend the same pipeline with the failure paths a Host app sees as Results or raises. verify_code returns a Result with :invalid_code when the wrong code is supplied. send_code returns a Result with :invalid_phone_number when normalisation fails. decode_token raises InvalidToken for tampered, expired, wrong-signing-key, and wrong-issuer Tokens. Config.validate! raises naming each missing required field. Phone.normalize raises InvalidPhoneNumber with the input redacted per ADR-0004.

Acceptance criteria
  • verify_code(phone, "anything-but-000000") → Result with error == :invalid_code.
  • send_code("not a phone") → Result with error == :invalid_phone_number (does not raise).
  • decode_token("garbage") raises InvalidToken.
  • decode_token of token signed with the wrong key raises InvalidToken.
  • decode_token of token with wrong iss raises InvalidToken.
  • decode_token of expired token raises InvalidToken.
  • Config.validate! raises naming the first missing field; passes when all required fields set.
  • InvalidPhoneNumber#message includes the redacted form; raw Phone never appears via to_s or inspect.
  • Each failure path has a dedicated sentence-style Minitest test.
  • bundle exec rake green.
03

Twilio Verify as the production OTP backend

AFK
Blocked by slice 01
Stories 10 14 31

A second OTP::Adapter implementation that wraps Twilio Verify. Configured by passing a TwilioAdapter instance into the Config; the same send_code / verify_code pipeline drives it. Adapter delegates to Twilio Verify's send and check endpoints via the twilio-ruby SDK. Failure modes map to the documented symbol vocabulary: 60200 → :invalid_phone_number, 60202 → :max_check_attempts, 60203 → :max_send_attempts, HTTP 401 → :twilio_authentication_error, 429 → :twilio_rate_limited, 5xx/timeout → :twilio_service_unavailable, fallback → :twilio_error. Tests use Mocha — no WebMock, no real HTTP.

Acceptance criteria
  • twilio-ruby in gemspec runtime deps; mocha in Gemfile dev deps.
  • With Config wired to a TwilioAdapter (Mocha-stubbed approval), send_code → success Result.
  • Same stubbing: verify_code → success Result with a Token decodable by decode_token.
  • Each of the seven Twilio failure cases maps to its specified error symbol — one test per mapping.
  • Unmapped Twilio codes fall through to :twilio_error.
  • Adapter never raises — every Twilio failure path produces a failure Result.
  • bundle exec rake green.
04

Rate-limit Verification sends per Phone

AFK
Blocked by slice 01
Stories 13 16 22 23

A RateLimiter that consults a pluggable Store and raises internally when a Phone exceeds the threshold within the window. Default Store: Stores::MemoryStore, mutex-protected in-process counter with sliding-window expiry. The top-level send_code invokes the limiter before delegating to the OTP adapter, so Twilio is never billed for rate-limited attempts. Internal RateLimited raise is caught and converted into Result.failure(:rate_limited) at the top level — internal raise, external Result, consistent with the convention.

Acceptance criteria
  • 6th send_code to the same Phone within an hour → Result with :rate_limited; OTP adapter not consulted.
  • Two different Phones each get their own 5-per-hour bucket — no cross-Phone interference.
  • Stubbing Time.now forward past the window resets the counter; send_code succeeds again.
  • MemoryStore is mutex-protected — concurrent-burst threads test shows no miscounts.
  • Store interface documented as #increment(key, window_seconds) → count; any conforming object passable via config.rate_limit_store.
  • config.rate_limit defaults to { per_phone: 5, window: 3600 }; overrides honoured.
  • bundle exec rake green.
05

test_mode! Rails-environment safety guard

AFK
Blocked by slice 01
Stories 26

Add the env guard from ADR-0002 around test_mode!. The method raises ConfigurationError unless Rails is loaded AND the current Rails env is test or development. In non-Rails contexts (no Rails constant defined), the method refuses outright. The guard's failure message states which environments allow Test mode and tells the developer how to swap the OTP adapter manually if they need Test mode outside Rails.

Acceptance criteria
  • In a Rails.env.test? context, test_mode! succeeds (regression test for slice 01).
  • In a Rails.env.development? context, test_mode! succeeds.
  • In a Rails.env.production? (or other non-test/dev) context, test_mode! raises ConfigurationError.
  • When Rails is not defined (simulated by undefining the constant), test_mode! raises ConfigurationError.
  • Error message names the allowed environments.
  • bundle exec rake green.
06

Rails Controller concern

AFK
Blocked by slice 01
Stories 06 07 32

A Bitsmithy::Auth::Controller concern that a Host-app ApplicationController mixes in. Reads and writes a Token in session[:bitsmithy_auth_token]. Exposes current_identity, current_phone, authenticated?, sign_in, sign_out. Memoised per request; memo invalidated on sign-in/sign-out. Loaded only when ActionController is defined at gem-load time. Deliberately omits require_authentication! — Host apps own redirect semantics. Tested via a minimal fake controller class exposing a session Hash; actionpack in Gemfile's :test group.

Acceptance criteria
  • actionpack in Gemfile :test group.
  • Concern file loaded only when ActionController is defined — confirmed by defined?(Bitsmithy::Auth::Controller) with/without ActionController.
  • Mixing into fake controller with valid Token in session: current_phone matches Token's sub.
  • Empty session: current_phone == nil and authenticated? == false.
  • Invalid Token in session: current_phone == nil (InvalidToken swallowed, not propagated).
  • sign_in(token:) writes session key; subsequent current_phone returns new phone (memo invalidated). phone: param dropped — Token's sub claim already carries it.
  • sign_out removes session key; subsequent current_phone returns nil.
  • No require_authentication! method defined on the concern.
  • bundle exec rake green.
